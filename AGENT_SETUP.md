# Set up PimpMyPantheon

These instructions work with any assistant or automation agent that has local terminal access, and can also be followed manually. Reading this repository is not authorization to install a schedule or interrupt a running application. Act within the user's request; do not ask again for choices or approval already supplied.

1. Read the README and inspect `pimp_my_pantheon.py`. Establish the user's daily local time (default 09:00) and which **local** Hermes installation to update. Explain that the first installation runs immediately and later updates briefly close an open app. Do not assume any publisher's machine, username, agent name, paths, or GitHub account applies to this user.
2. Check macOS, Python 3.9+, Git, `command -v hermes`, and `hermes update --help`. Run `hermes --version` and `hermes update --plan`; verify the actual installation directory, update options, profiles/services affected, and Git install method. Hermes needs `--yes`, `--keep-stash`, `--plan`, and structured update receipts. If this version lacks those capabilities, explain the missing prerequisite; do not invent flags or install a second copy.
3. Discover the actual built Desktop app under that checkout, or use an explicit user-supplied app path. Inspect `Contents/Info.plist`: the expected bundle ID is `com.nousresearch.hermes`, not `com.nousresearch.hermes.setup`. Do not choose an arbitrary app when several builds exist. Configure the build under `apps/desktop/release/` even when `/Applications/Hermes.app` is an identical copy; the utility recognizes and reopens that copy itself. This utility targets one local installation per macOS user, not remote-only desktop connections or SSH fleets.
4. Inspect any existing `~/Library/Application Support/PimpMyPantheon/config.json` and `~/Library/LaunchAgents/com.tokenfires.pimpmypantheon.plist`. Preserve existing options unless the user asks to change them. Check for any other user-created Hermes update schedule to avoid duplicates; do not delete unrelated jobs. The scheduler must be a local LaunchAgent, not an AI task, cloud workflow, or recurring conversation.
5. For an existing installation, run `python3 pimp_my_pantheon.py run --dry-run`. For a new installation, make a **private temporary configuration** using `config.example.json` as a schema, replacing placeholder paths with observed paths and an appropriate PATH. Then run `python3 pimp_my_pantheon.py run --config /absolute/private/config.json --state-dir /absolute/private/preview --dry-run`. Read the resulting report. Preview may run Hermes's passive version check; it does not quit, install an update, or restore a pending app. Do not repair source modifications, force branch switches, discard files, or bypass active work just to get an eligible result.
6. Verify the user's normal unattended authentication if needed. The utility must keep their configured Git/package credentials; never print tokens or copy credentials into this repository. Do not switch them to the repository publisher's GitHub account. No new AI model credentials are needed.
7. When installation is authorized and preview is eligible, use a stable Python path to run `python3 pimp_my_pantheon.py install --at HH:MM`, supplying discovered `--hermes`, `--checkout`, `--hermes-home`, and `--app` overrides if necessary. Existing installs require `--replace`; omission preserves previous options. Do not run as root. Installation starts the first update immediately.
8. Inspect `status`, the LaunchAgent, and the new local report. Wait for the update to finish; do not claim completion while it runs. Confirm the report matches this run's time, the installed revision, Hermes's updater PID and receipt, and the reopen health check when the app was initially open. Report skips or failures honestly and restore the app within the user's authorized scope. Do not bypass missing/partial receipts to force a success banner.
9. Scheduled runs notify by default. If useful, `python3 pimp_my_pantheon.py notify` replays the saved result once with **no update**. Do not loop this command while waiting for a screenshot. macOS can attribute the sender to Script Editor, and Focus/settings affect visibility. Successful submission alone does not prove a visible notification.
10. Hand off the schedule, outcome, local report/config paths, notification status, and `uninstall` command. Tell the user that failed or skipped scheduled attempts wait until the next day; `run --notify` retries immediately. No agent should remain running to manage this utility. On another Mac, repeat discovery rather than copying one machine's config.

For maintenance, inspect new source then reinstall with `--replace`; a Git pull alone does not update the installed snapshot. If `pending.json` exists, resolve interrupted recovery through a real run before replacement or uninstall. Never publish configuration, raw logs, receipts, personal profiles, secrets, or broad desktop screenshots. The public repository should contain only reusable code, instructions, tests, and deliberately reviewed illustrations.
